# Reality Artifact Specification

## Overview

Reality Artifacts are the atomic units of truth in the 0xSCADA ecosystem. Each artifact represents a cryptographically verifiable piece of industrial reality—what happened, what was proven, or why a decision was made.

## Artifact Identity

Every artifact is uniquely identified by its **content-addressed SHA256 hash**. This ensures:
- Immutability: any change produces a different ID
- Deduplication: identical artifacts share the same ID
- Verification: integrity can be checked at any time

## Artifact Schema

```json
{
  "$schema": "https://0xscada.local/schemas/artifact-v1.json",
  "id": "<SHA256 hash of canonical content>",
  "version": "1.0.0",
  "timestamp": "<ISO 8601 datetime with timezone>",
  "origin": {
    "type": "<system | agent | fork>",
    "identifier": "<unique identifier of origin>",
    "signature": "<optional cryptographic signature>"
  },
  "scope": {
    "domain": "<linux | ethereum | agentic-qe | cross-domain>",
    "subsystem": "<optional subsystem identifier>",
    "tags": ["<optional>", "<categorization>", "<tags>"]
  },
  "dependencies": [
    {
      "id": "<SHA256 hash of dependency>",
      "relationship": "<requires | extends | supersedes | references>"
    }
  ],
  "content": {
    "type": "<trace | proof | witness | snapshot | twin | embedding | worldmodel>",
    "encoding": "<raw | base64 | lfs-pointer>",
    "size": "<size in bytes>",
    "checksum": "<SHA256 of raw content>"
  },
  "summary": "<human-readable description of what this artifact represents>"
}
```

## Field Definitions

### `id` (required)
- SHA256 hash of the canonical JSON representation (excluding the `id` field itself)
- Format: 64 lowercase hexadecimal characters
- Example: `a3f2b8c1d4e5f67890abcdef1234567890abcdef1234567890abcdef12345678`

### `version` (required)
- Semantic version of the artifact schema
- Current version: `1.0.0`

### `timestamp` (required)
- ISO 8601 formatted datetime with timezone
- Example: `2024-01-15T14:32:07.123Z`
- Must represent the moment the artifact was captured

### `origin` (required)
- **type**: One of:
  - `system`: Generated by kernel/hardware (ftrace, eBPF, firmware)
  - `agent`: Generated by autonomous agent decision
  - `fork`: Generated by a 0xSCADA fork (linux-fork, geth-fork, agentic-qe)
- **identifier**: Unique ID of the originating entity
- **signature**: Optional Ed25519 or secp256k1 signature for authenticity

### `scope` (required)
- **domain**: Primary domain of applicability
  - `linux`: Kernel traces, system calls, hardware events
  - `ethereum`: Proofs, state diffs, zero-knowledge witnesses
  - `agentic-qe`: Agent reasoning, embeddings, world models
  - `cross-domain`: Artifacts spanning multiple domains
- **subsystem**: Optional narrower categorization
- **tags**: Optional array of classification tags

### `dependencies` (optional)
Array of artifacts this artifact depends on:
- **id**: SHA256 hash of the dependency
- **relationship**:
  - `requires`: Must exist for this artifact to be valid
  - `extends`: Builds upon the referenced artifact
  - `supersedes`: Replaces the referenced artifact
  - `references`: Informational reference only

### `content` (required)
- **type**: The artifact type (trace, proof, witness, etc.)
- **encoding**: How the content is stored
  - `raw`: Inline JSON-compatible content
  - `base64`: Binary content encoded as base64
  - `lfs-pointer`: Git LFS pointer for large files
- **size**: Size in bytes of the raw (decoded) content
- **checksum**: SHA256 of the raw content for verification

### `summary` (required)
- Human-readable description
- Should answer: "What does this artifact represent?"
- Maximum 500 characters

## Content Types

### Traces (`*.trace`, `*.ftrace`)
Kernel and system execution traces capturing the "what happened" layer.

### Proofs (`*.proof`, `*.zk`)
Cryptographic proofs of computation or state transitions.

### Witnesses (`*.witness`)
Data that enables verification of proofs without full recomputation.

### Snapshots (`*.snapshot`)
Point-in-time captures of system or process state.

### Twins (`*.twin`)
Digital twin representations of physical systems.

### Embeddings (`*.embedding`)
Vector representations of agent knowledge or system state.

### World Models (`*.worldmodel`)
Agent's learned representations of system behavior.

## Canonical Serialization

For computing artifact IDs:
1. Remove the `id` field from the artifact
2. Serialize to JSON with:
   - Keys sorted alphabetically (recursive)
   - No whitespace
   - UTF-8 encoding
3. Compute SHA256 of the resulting bytes

## Verification

To verify an artifact:
1. Extract the claimed `id`
2. Recompute the canonical hash (excluding `id`)
3. Compare: if mismatch, artifact is corrupted or tampered
4. Verify `content.checksum` against actual content
5. Recursively verify all dependencies

## Storage

- Small artifacts (< 1MB): Inline in repository
- Large artifacts (≥ 1MB): Git LFS with pointers
- All artifacts: Content-addressed for deduplication
